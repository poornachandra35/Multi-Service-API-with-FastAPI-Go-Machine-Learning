📌 Multi-Service API Platform — Developer Guide

Modular FastAPI services: CSV Analyzer, Sentiment Analyzer, Number Series Predictor, Animal Classifier (vision), Stock Predictor (ANN). Use this guide to integrate, run, and extend the APIs.

Ready for Integration

Overview

This repository provides a compact, modular FastAPI application that exposes multiple developer-friendly services. Each module lives under modules/ and registers its own router in main.py. The design favors clear separation of concerns, lightweight inference, and easy integration from other projects via HTTP calls.

Architecture

FastAPI app → Routers per feature → Optional ML models under modules/stock_predictor/model/. Designed for both local development and cloud hosting (Render, Heroku, any cloud VM).

FrameworkFastAPI + Uvicorn
ML libsTensorFlow (for stock), Transformers, scikit-learn
IntegrationHTTP REST endpoints (JSON & multipart)

Design principles

  • Small, testable modules (single responsibility)
  • Load ML models at startup for fast inference
  • Provide clear validation and helpful error messages
  • Offer language-agnostic integration examples

Modules — Detailed

Detail for each module: purpose, internal flow, expected inputs/outputs, error conditions, response schemas, and small SVG flow diagrams.

CSV Analyzer

Purpose: Upload a CSV and receive a structured JSON summary. Useful for quick EDA, data validation, and light cleaning operations from any client.

Internal flow
  1. Endpoint expects multipart/form-data with a file field file.
  2. Server loads file with pandas.read_csv() into a DataFrame.
  3. Computes head(), dtypes, descriptive stats, null counts, unique counts.
  4. Optionally runs simple cleaning suggestions (drop constant columns, impute nulls) and returns actions.
Input: multipart file field named file (CSV).
Output: JSON with fields: preview, summary, missing, suggested_cleaning.

Response Schema

FieldTypeDescription
previewarray[object]First N rows (as objects)
summaryobjectDescriptive stats per numeric column (mean, std, min, max)
missingobjectNull counts per column
suggested_cleaningarray[string]List of suggested cleaning actions

Sentiment Analyzer

Purpose: Classify the sentiment of text using a transformer model or a lightweight classifier depending on deployment constraints.

Internal flow
  1. Accepts JSON body { "text": "..." }.
  2. Tokenize using the selected tokenizer, run the model, apply softmax to get probabilities.
  3. Return label and score; optionally include token-level attention/highlights if implemented.
Input: JSON {"text": "I love this"}.
Output: {"label":"positive","score":0.95} or detailed scores.

Response Schema

FieldTypeDescription
labelstringPredicted sentiment label (positive/neutral/negative)
scorefloatConfidence score for the label (0-1)
scoresobject (optional)Per-label probabilities

Number Series Predictor

Purpose: Detect simple numerical patterns (arithmetic, geometric, polynomial) and predict the next term(s). Good for puzzles, basic forecasting, or educational demos.

Internal flow
  1. Receive JSON { "series": [ ... ] }.
  2. Run heuristic checks: constant diff (arithmetic), constant ratio (geometric), polynomial fit, repeating patterns.
  3. Return detected pattern, next term(s), and an explanation string.
Input: numeric array (len ≥ 3).
Output: {"detected":"arithmetic","next":5,"rule":"+1 each step"}.

Response Schema

FieldTypeDescription
detectedstringDetected rule (arithmetic, geometric, polynomial, repeating)
nextnumberPredicted next term
rulestringHuman-readable explanation

Animal Classifier (Image)

Purpose: Classify uploaded images into animal classes. Uses PIL for preprocessing and a model for inference.

Internal flow
  1. Client uploads image via multipart/form-data.
  2. Server resizes/crops, normalizes pixel values, converts to model tensor.
  3. Model runs inference and returns top-k labels with confidence.
Input: multipart file field image.
Output: {"label":"dog","score":0.98,"top_k":[...]}.

Response Schema

FieldTypeDescription
labelstringTop predicted class
scorefloatConfidence for top class
top_karray[object]Optional list of top-k {label, score}

Stock Predictor (ANN)

Purpose: Predict the next day's close using a pre-trained ANN. The model expects 5 previous close prices by default, uses min-max normalization stored in min.npy and max.npy, and returns a denormalized price.

Model expectations & flow
  1. Model files must be under modules/stock_predictor/model/.
  2. On startup, model_loader.py should load stock_ann.h5 and scaler values with np.load.
  3. Input normalization: norm = (prices - min) / (max - min).
  4. Model predicts on reshaped input (1,5). Denormalize result with pred*(max-min)+min.
Validation: If input length ≠ 5, return HTTP 400 with helpful message. Check input ranges against training scale to avoid meaningless predictions.

Response Schema

FieldTypeDescription
next_day_predictionfloatPredicted next day closing price (denormalized)

Integration Examples

Replace https://your-app.onrender.com with your deployed URL or http://127.0.0.1:8000 during local testing. Each code block includes a copy button.

cURL — Stock Predictor

curl -X POST https://your-app.onrender.com/stock/predict \
  -H "Content-Type: application/json" \

Java (HttpClient) — Stock Predictor

import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;

String json = "{\"previous_prices\":[1580,1590,1605,1612,1601]}";

HttpClient client = HttpClient.newHttpClient();
HttpRequest req = HttpRequest.newBuilder()
    .uri(URI.create("https://your-app.onrender.com/stock/predict"))
    .header("Content-Type","application/json")
    .POST(HttpRequest.BodyPublishers.ofString(json))
    .build();

HttpResponse res = client.send(req, HttpResponse.BodyHandlers.ofString());
System.out.println(res.body());

422 {"detail":[{...validation errors...}]} FastAPI/Pydantic validation error — type mismatch or missing field in request body.

Stock Predictor — Deep Dive

Exact expectations, normalization math, retraining tips, and troubleshooting notes so integrators know how to prepare input data and what to expect from responses.

Model Loader

A lightweight loader module (e.g., modules/stock_predictor/model_loader.py) should:

  • Load TensorFlow model with tf.keras.models.load_model(path, compile=False).
  • Load normalization values: min.npy and max.npy (scalars saved by training script).
  • Provide a method predict_next(previous_prices:list[float]) -> float that normalizes input, runs inference, and denormalizes the output.

Normalization

StepFormula
Normalize inputnorm = (prices - min) / (max - min)
Model predictp = model.predict(norm.reshape(1,-1))[0][0]
Denormalizedenorm = p * (max - min) + min

Retraining tips

  • If you need predictions in a lower price range (e.g., 0–100), retrain with a synthetic dataset using base_price in that range.
  • Save min.npy and max.npy exactly as scalars; the loader expects these shapes.
  • Prefer CPU-only TensorFlow for small cloud instances; disable GPU compile with compile=False.

Common Errors & Fixes

  • 400 Bad Request — Wrong input length. Ensure you send exactly 5 values (unless retrained).
  • Model file not found — Ensure model files are in modules/stock_predictor/model/ and committed to repo or available at runtime.
  • Unrealistic predictions — Ensure the input scale matches training data; otherwise, retrain or rescale inputs.

FAQ & Best Practices

Common questions for developers integrating the Multi-Service API, along with best practices for stable usage, error handling, and performance.

1. What is the recommended method to call the API?

You can call the API using any HTTP client: JavaScript fetch, Python requests, Java HttpClient, C#, Flutter, or cURL. Always set Content-Type: application/json for JSON-based endpoints.

2. Do I need an API key?

Currently, no API key is required. However, in production you should implement authentication if exposing the service publicly.

3. What happens if I send invalid or missing fields?

The API returns a structured FastAPI validation error message with HTTP 422 or 400. Always validate request data before calling the API.

4. Why does the stock predictor require exactly 5 values?

The model was trained with a fixed input window of 5 previous closing prices. If your use case requires a different window size, the model must be retrained by the project maintainer. Users cannot modify the backend or upload their own models.

5. Why is my stock prediction unrealistic?

The model expects values in the same price range it was trained on. If you send values far outside that range, the prediction may not make sense. Try normalizing your inputs or using realistic values.

6. How big can my CSV upload be?

CSV uploads depend on server limits. For best performance, keep CSV files under 20 MB. For extremely large files, consider chunking or using streaming pipelines.

7. I get a CORS error in frontend. What should I do?

CORS is enabled for all origins in the backend (allow_origins=["*"]). If your app blocks requests, ensure your browser or framework isn't overriding CORS rules.

8. Can I integrate this API with React, Angular, Vue, or Flutter?

Yes. The API uses simple JSON responses, so it integrates smoothly with any frontend or mobile framework. See integration examples in the section above.

9. Does the Sentiment Analyzer support languages other than English?

The default model is trained primarily on English. For multilingual support, the backend maintainer must load a multilingual transformer model.

10. What image formats work for the Animal Classifier?

JPG, JPEG, and PNG are fully supported. The file must be provided via multipart/form-data with the field name image.

11. What status codes does the API use?

  • 200 – Success
  • 400 – Bad request (invalid input format)
  • 404 – File missing or incorrect route
  • 422 – Validation error
  • 500 – Internal server error

12. Can I use this API in a production app?

Yes. The API is modular and production-ready, but high traffic deployments should include: rate limiting, caching, logging, and authentication.

Best Practices for Developers

  • Validate user inputs before sending requests.
  • Use async HTTP clients where possible for better performance.
  • Cache repeated requests (e.g., identical sentiment analysis queries).
  • Retry on network failures with exponential backoff.
  • Handle all HTTP errors gracefully in your UI.
  • Upload clean, well-formatted CSV files for best results.
  • Compress images before sending them to Animal Classifier.
  • Do not spam endpoints — follow good API hygiene.
